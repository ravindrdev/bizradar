1. Google Places Text Search
═══════════════════════════════════════════════════════════════════════════════
WHAT API GIVES
- name
- formatted_address
- rating
- user_ratings_total
- types[]
- business_status
- place_id
- geometry.location.lat / lng
- photos[] (max 10)
- price_level
|
WHAT GROWTHIM TAKES
- name → data.name
- formatted_address → data.formatted_address
- rating → data.google_rating
- user_ratings_total → data.google_review_count
- types → data.google_types (NAICS routing only)
- business_status → data.business_status
- place_id → data.place_id
- geometry.location → data.latitude, data.longitude
- photos.length → data.photo_count (NULL when length >= 10)
- IGNORES: price_level (never stored)
- IGNORES: photo URLs/widths
|
WHAT CLAUDE RECEIVES
- "Business: AmericInn by Wyndham Dodgeville"
- "Address: 3637 WI-23, Dodgeville, WI 53533, USA"
- "Rating: 4.2 stars (354 reviews)"
- Photo count line OMITTED entirely when null (>=10 photos)
- business_status / types / place_id used internally; never in prompt

2. Google Place Details
═══════════════════════════════════════════════════════════════════════════════
WHAT API GIVES
- reviews[] (max 5, sorted by relevance — NOT date)
  - author_name, rating, text, time, language
- website
- opening_hours.weekday_text[] (7-day array)
- opening_hours.open_now
- formatted_phone_number
- photos[] (max 10)
- name (override of search)
|
WHAT GROWTHIM TAKES
- reviews → data.sample_reviews (sliced to 5, { text, stars })
- reviews.length → data.reviews_sampled
- reviews owner-replies → respondsToReviews (FORCED NULL — disabled)
- reviews[0].time → reviewRecencyDays (FORCED NULL — disabled)
- website → data.website_url (then HEAD-checked → data.website_exists)
- opening_hours.weekday_text.length===7 → data.hours_complete
- opening_hours.open_now → data.is_open_now
- photos.length → data.photo_count (same cap rule as #1)
- IGNORES: formatted_phone_number
- IGNORES: photo URLs
- IGNORES: review author_name + language
|
WHAT CLAUDE RECEIVES
- "Hours complete: true"
- "Website loads: true"
- "Recent reviews (sample):"
- "★5: Stayed for the weekend for some peace and quiet..."
- "★5: This is a wonderful hotel..."
- "★3: Room was okay. AC was loud..."
- Response rate line REMOVED entirely (banned metric)
- Review recency line REMOVED entirely (banned topic)
- Photo count line OMITTED when null

4. Google PageSpeed Insights
═══════════════════════════════════════════════════════════════════════════════
WHAT API GIVES
- lighthouseResult.categories.performance.score (0-1)
- lighthouseResult.audits.interactive.numericValue (ms)
- lighthouseResult.audits.largest-contentful-paint.numericValue (ms)
- lighthouseResult.audits.total-blocking-time.numericValue (ms)
- Plus full audits tree (90+ audits), accessibility/best-practices/SEO scores
|
WHAT GROWTHIM TAKES (fetchPageSpeed)
- perfScore × 100 (rounded) → data.website_mobile_score, data.pagespeed.mobile_score
- interactive / 1000 (1dp) → data.load_time_seconds, data.pagespeed.load_time_seconds
- LCP / 1000 (1dp) → data.pagespeed.lcp_seconds
- perfScore >= 50 → data.is_mobile_friendly, data.pagespeed.is_mobile_friendly
- Whole pagespeed object → data.pagespeed
- IGNORES: accessibility/best-practices/SEO categories
- IGNORES: TBT (computed but not stored)
- IGNORES: every other lighthouse audit (TTFB, CLS, FCP, etc.)
|
WHAT CLAUDE RECEIVES
- "Website mobile quality (Google PageSpeed Insights):"
- "Mobile score: 25/100 (below mobile-friendly threshold)"
- "Time-to-interactive: 15.2s — above 3-second abandonment threshold (S040)"
- Section OMITTED entirely when pagespeed null (e.g. 15s timeout)
- Section OMITTED when website_exists is false (PSI never fires)

5. Google Geocoding
═══════════════════════════════════════════════════════════════════════════════
WHAT API GIVES
- results[].geometry.location.{lat,lng}
- results[].formatted_address
- results[].place_id
- results[].address_components[]
- results[].types[]
|
WHAT GROWTHIM TAKES
- Used INTERNALLY by googlePlaces.findPlace as a fallback path when
  Text Search returns low-confidence (<120) results
- lat/lng → seeds findPlace's nearby radius search to disambiguate
- formatted_address → passed back as candidate (toResult)
- Result merges back into the same Place Details flow as #1
- IGNORES: address_components (never parsed for components)
- IGNORES: place_id, types (Text Search already provided these)
|
WHAT CLAUDE RECEIVES
- NOTHING DIRECTLY
- Geocoding is internal disambiguation only — its output is consumed
  by findPlace and never exposed to the user prompt

6. US Census ACS (income / population)
═══════════════════════════════════════════════════════════════════════════════
WHAT API GIVES (URL: /data/2024/acs/acs5)
- B19013_001E — median household income (dollars)
- B01001_001E — total population (sex-by-age table sum)
- B25010_001E — average household size (persons)
- Also: place-level call returns NAME, plus same fields scoped to a place
- Sentinel value -666666666 = data not available
|
WHAT GROWTHIM TAKES (fetchCensusByZip)
- B19013_001E → data.median_household_income
  (city place-level if matched, else ZCTA, else county for big cities)
- B01001_001E → data.total_population (city place-level preferred)
- B25010_001E → data.average_household_size
- zip → data.census_zip
- Resolution provenance → census.population_source ('city'|'zip'),
  income_source ('city'|'county'|'zip')
- IGNORES: -666666666 sentinel (filtered to null)
- IGNORES: place NAME beyond the match step
|
WHAT CLAUDE RECEIVES
- "Local demographics (ZIP 53533):"
- "Median household income: $72,288"
- "Population: 5,042"
- (Average household size is in the bundle but not rendered to the prompt)
- (population_source / income_source flags not rendered)

7. Census Housing (piggybacks on call #6)
═══════════════════════════════════════════════════════════════════════════════
WHAT API GIVES (same /2024/acs/acs5 call, additional fields)
- B25001_001E — total housing units
- B25002_003E — vacant housing units
- B25003_002E — owner-occupied units
- B25003_003E — renter-occupied units
- B25077_001E — median home value (dollars)
- B25064_001E — median gross rent (dollars/month)
|
WHAT GROWTHIM TAKES (derived inside _fetchCensusZipLevel)
- totalUnits → data.census_housing.housing_units
- (vacant/total) × 100, 1dp → data.census_housing.vacancy_rate
- (owner/(owner+renter)) × 100, 1dp → data.census_housing.homeownership_rate
- B25077_001E → data.census_housing.median_home_value
- B25064_001E → data.census_housing.median_gross_rent
- IGNORES: raw owner/renter counts (only the ratio is exposed)
- IGNORES: vacant count (only the ratio is exposed)
|
WHAT CLAUDE RECEIVES
- "Local housing market (Census ACS, ZIP-level):"
- "  Housing units: 4,521 · Vacancy rate: 8.2% · Homeownership rate: 68.4% · Median home value: $187,000 · Median gross rent: $842/mo"
- Section OMITTED when census_housing null

8. Open-Meteo Weather
═══════════════════════════════════════════════════════════════════════════════
WHAT API GIVES (archive-api.open-meteo.com/v1/archive)
- daily.time[] (past 12 months of dates)
- daily.temperature_2m_max[] (daily highs)
- daily.precipitation_sum[]
- Plus timezone, hourly arrays (not used)
|
WHAT GROWTHIM TAKES (fetchWeather)
- Computes monthly avgs from daily highs
- Peak month (highest avg temp) → data.peak_month + data.weather.peak_month
- Jun/Jul/Aug presence → data.peak_tourist_season ('Jun-Aug' etc.)
- Any month avg < 35°F → data.has_cold_winter (boolean)
- Any month avg > 85°F → data.has_hot_summer (boolean)
- Whole weather object → data.weather
- IGNORES: daily precipitation arrays (computed but not exposed)
- IGNORES: timezone, hourly resolution
|
WHAT CLAUDE RECEIVES
- "Weather / seasonality (Open-Meteo, past 12 months):"
- "Peak month: July"
- "Peak tourist season: Jun-Aug"
- "Cold winter (any month avg < 35°F): true"
- "Hot summer (any month avg > 85°F): false"

10. Foursquare Places
═══════════════════════════════════════════════════════════════════════════════
WHAT API GIVES (places-api.foursquare.com/places/search)
- results[].name
- results[].categories[0].fsq_category_id + .name
- results[].distance (meters)
- results[].location.address
- results[].hours (open_now, display)
- results[].fsq_id, geocode, related_places, etc.
|
WHAT GROWTHIM TAKES (fetchNearbyVenues)
- Each result passes through TWO filters before keep:
  - STEP 1: closed_bucket filter (currently dead — field not returned by /search)
  - STEP 2: Google Text Search cross-check via isVenueOpen
    (drops if Google says CLOSED_PERMANENTLY/CLOSED_TEMPORARILY)
- name → nearby_venues[].name
- categories[0].name (mapped via FSQ_TOP_CATEGORY_LABEL) → nearby_venues[].category
- distance → nearby_venues[].distance_meters
- null (popularity unsupported on new API) → nearby_venues[].popularity
- venuesRes.value → data.nearby_venues
- venuesRes.value.length → data.nearby_venue_count
- IGNORES: fsq_id, hours, location.address (used only for cross-check)
- IGNORES: closed_bucket value (field absent on /search responses)
|
WHAT CLAUDE RECEIVES
- "Nearby venues within 1km (Foursquare — food, arts, outdoors):"
- "  • Jokers Wild (arts_and_entertainment, 105m)"
- "  • The Thym's (food_and_drink, 105m)"
- (Hills Pub & Banquet Hall is DROPPED — Google reports CLOSED_PERMANENTLY)

11. OpenStreetMap Overpass
═══════════════════════════════════════════════════════════════════════════════
WHAT API GIVES (Overpass QL POST)
- elements[].tags.{name, shop, amenity, highway, railway, ...}
- elements[].lat, lon (nodes)
- elements[].center.{lat,lon} (ways/relations via `out center tags`)
- elements[].type (node|way|relation), id
|
WHAT GROWTHIM TAKES (fetchLocationSignals)
- ANCHORS (within 500m):
  - tags.shop ∈ {supermarket, department_store, mall} OR
    name matches big-box regex (Walmart/Target/...)
  - → location_signals.anchor_tenants[] (string array, max 10)
  - .length → location_signals.anchor_tenant_count
- TRANSIT (within 800m):
  - tags.highway === 'bus_stop' OR tags.railway === 'station'
  - min(distance) → location_signals.nearest_transit_meters
  - distance ≤ 400m → location_signals.has_transit_nearby (boolean)
- Result also written top-level: data.anchor_tenants, data.anchor_tenant_count,
  data.nearest_transit_meters, data.has_transit_nearby
- IGNORES: all other tags (cuisine, opening_hours, etc.)
- IGNORES: parks (parks code was reverted — anchors + transit only)
|
WHAT CLAUDE RECEIVES
- "On-the-ground location signals (OpenStreetMap):"
- "Anchor tenants within 500m: (none found within 500m) (0 total)"
- "Transit: (no transit found within 800m)"
- OR when populated:
- "Anchor tenants within 500m: Target, Aldi (2 total)"
- "Transit: 177m to nearest bus stop / rail station — transit-served"

12. HUD Building Permits
═══════════════════════════════════════════════════════════════════════════════
WHAT API GIVES (TWO-STEP)
- Step 1 — Census geocoder: county FIPS-5 from street/city/state address
- Step 2 — HUD ArcGIS FeatureServer (Residential_Construction_Permits...):
  - features[0].attributes.cnty_name (county name)
  - features[0].attributes.year
  - features[0].attributes.total_units
  - features[0].attributes.single_family
  - features[0].attributes.{year-1}.total_units (for YoY)
|
WHAT GROWTHIM TAKES (fetchBuildingPermitsByAddress)
- countyFIPS → data.county_fips
- county_name → data.county_name
- year → data.building_permits_year + building_permits.year
- total_units → data.building_permits_total + building_permits.total
- single_family → data.building_permits_single_family + building_permits.single_family
- ((this_year - last_year) / last_year × 100, 1dp) → data.building_permits_yoy_change
- Whole object → data.building_permits
- IGNORES: multi-family-only counts
- IGNORES: years older than year-1
- IGNORES: ArcGIS geometry/object IDs
|
WHAT CLAUDE RECEIVES
- "County building permits (Iowa County, 2022, HUD/Census BPS):"
- "Total residential permits: 68"
- "Single-family: 51"
- "Trend: declining market (-50.7% YoY)"
- (Trend classification: >+5% growing, <-5% declining, between = stable)

15. TripAdvisor Content API
═══════════════════════════════════════════════════════════════════════════════
WHAT API GIVES (3 chained calls)
- /location/search: data[0].{location_id, name, address_obj}
- /location/{id}/details:
  - rating, num_reviews
  - ranking_data.{ranking_position, ranking_out_of, ranking_string}
  - subratings[].{name, value}
  - awards[].{award_type, year}
  - trip_types[].{name, value}
- /location/{id}/reviews:
  - data[].{rating, title, text, trip_type, published_date}
|
WHAT GROWTHIM TAKES (fetchTripAdvisor)
- rating → data.ta_rating + tripadvisor.rating
- num_reviews → data.ta_review_count
- ranking_position, ranking_out_of → data.ta_ranking_position, data.ta_ranking_out_of
- subratings → data.ta_subratings + tripadvisor.subratings
- awards (first 5, {type, year}) → data.ta_awards + tripadvisor.awards
- trip_types → data.ta_trip_types + tripadvisor.trip_types
- reviews (first 3) → data.ta_recent_reviews (rating/title/snippet/trip_type)
- value subrating < overall - 0.4 → data.ta_value_gap_detected (boolean)
- Whole object → data.tripadvisor
- IGNORES: review published_date, full review text (snippet only)
- IGNORES: awards past index 5
- IGNORES: address_obj (already have it from Google)
|
WHAT CLAUDE RECEIVES
- "TripAdvisor data (Content API):"
- "Overall: 4.0★ across 89 reviews"
- "Ranked #3 of 12 locally"
- "Sub-ratings:"
- "    service: 4.5"
- "    value: 4.0"
- "    cleanliness: 4.5"
- "Awards: Travelers' Choice (2024)"
- "Trip-type mix (counts): families=24, couples=31, solo=8, business=2, friends=12"
- "Recent reviews:"
- "    [5★ · couples] Great stay: clean rooms, friendly staff..."
- Plus optional line when applicable:
- "Value-perception gap detected: value sub-rating trails overall rating by ≥0.4..."

18. USDA ERS
═══════════════════════════════════════════════════════════════════════════════
WHAT API GIVES (api.ers.usda.gov/data/arms/farmeconomics)
- data[].{Value, year, state, variable, ...}
- Many ARMS variables available (NETSALES, OPEXP, NETINCOME, etc.)
|
